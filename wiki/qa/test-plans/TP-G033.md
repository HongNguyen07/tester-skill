  vòng đời riêng của QR (OOS01) · lịch sử link / khôi phục link cũ (OOS02) · thống kê vào nhóm (OOS04) · in QR (OOS05) · tuỳ biến QR (OOS06) ·

  2. **Tài liệu kỹ thuật của dev** cho 4 API (lấy link/QR, tạo, đổi, huỷ): endpoint, HTTP status, body lỗi — cần để viết kỳ vọng E01 "Gọi API thẳng → từ chối" (Q-13, hard gate security) và phân loại phản hồi hub {có link / chưa có link / lỗi} cho E03 (Q-09). Tài liệu này không có trong `tailieu/`.
  3. Ma trận API hub khả dụng theo môi trường (OQ04/Q-02) và nhánh QR của build (Q-01).
  4. Môi trường có đủ dữ liệu mục 3 (2 workspace, vai Gopany × Zalo, nhóm có/chưa có link, điện thoại + app Zalo, công cụ gây lỗi hub/mạng, quyền đọc log).
  5. BA quyết định các dẫn chiếu treo / mâu thuẫn spec (Q-31, Q-32, Q-35) — nếu chưa, chỉ chạy các case không phụ thuộc; case regression "Mời qua link" giữ ❓.
  6. FE + BE G033 đã deploy lên staging (thay cho `be.done + fe.done`; sẽ đối chiếu `deps.qa` khi có FEAT).
  - **Test-DESIGN KHÔNG chờ các entry trên** (shift-left): viết plan/case ngay, đánh ❓ chỗ bị chặn.
- **Exit (sign-off)** — theo `projectConfig.qa.exitCriteria`:
  - AC coverage = **100%** (mỗi AC §11 ≥ 1 test case; E01–E08, AF01–AF03/AF05–AF08, 4 chuyển trạng thái §7). Case ❓ phải được **giải ❓** (BA/dev trả lời) hoặc có **ghi nhận miễn trừ bằng văn bản của BA/PM** — không được tính ❓ là đã phủ/đã pass.
  - Blocking severity pass = **100%**; open critical defects = **0**. Case thuộc hard gate `security-test` (phân quyền, cả lối vào 2, gọi API thẳng), `multi-tenant-isolation` (rò link chéo workspace) và `cross-service-e2e` (người nhận không vào thẳng nhóm; đổi/huỷ làm link cũ chết) coi là **blocking**.
  - Evidence đầy đủ (screenshot/log/HAR/trace) cho mọi case pass (`reportEvidence: true`). Case pass nhưng thiếu evidence = chưa pass.
  - AC chưa có trong spec (a11y, tenant, log/audit, E02/E04 ở lối vào 2, thu hồi quyền giữa chừng — INTAKE §7) phải được BA bổ sung AC hoặc ghi nhận ngoài phạm vi trước sign-off.

### 5.1 Ảnh hưởng tới test focus

- **`security-test`:** BR04/E01 — dòng ẩn hoàn toàn khi không quyền; **lối vào 2 ("Mời qua link") cùng điều kiện** (Q-11, điểm dễ rò rỉ nhất); gọi trực tiếp 4 API khi không quyền → từ chối + "Ghi log truy cập trái phép"; thu hồi quyền khi màn/hộp xác nhận đang mở (Q-12, convention G014 BR19 làm kỳ vọng đề xuất ❓); thao tác ghi (Tạo/Đổi/Huỷ) bị từ chối ở API khi không quyền.
- **`multi-tenant-isolation`:** negative cross-workspace UI + API (mục 3); G033 thiếu AC `BR-C01` → nghĩa BR-C01 chỉ suy ra từ cách spec khác dùng (INTAKE Q-26) → kỳ vọng ghi "đề xuất, chờ BA".
- **`cross-service-e2e`:** hub là dependency ngoài → tách tập E2E Zalo thật (nhóm test riêng, người nhận trên app Zalo) và tập giả lập lỗi hub; E08 ghi error log kèm nguyên văn mã lỗi Zalo.
- **`regression-scope`:** thay đổi hành vi nút "Mời qua link" đã ship (breaking, G033 L563) → bảng 1.3; AC G008 L455 hiện hành sẽ sai.
- **`flaky-risk`:** thao tác "chờ Zalo xác nhận" (async), BR-C12 "cập nhật ngay", ngưỡng 2s/10s/3s/1s → chiến lược chống flaky ở mục 3.
